# ТЗ: Голосовой ввод в GetReplies

## 1. Цель

Дать пользователю возможность надиктовать текст голосом вместо печати —
в двух местах, где сейчас есть только textarea:

1. **Главная страница** (`app/page.tsx`) — поле ввода CV/Cover Letter перед polish.
2. **Mock Interview** (`app/interview/page.tsx`) — ответ кандидата на вопрос интервьюера.

Это разные по смыслу кейсы (диктовка текста vs. устный ответ на собеседовании),
но техническая реализация одна и та же — переиспользуемый компонент.

## 2. Почему не Web Speech API (`SpeechRecognition`)

Браузерный `webkitSpeechRecognition` — бесплатный и без сервера, но:

- не работает в Firefox, ограниченно в Safari (только через отдельный флаг/версии);
- требует постоянного интернет-соединения с серверами Google, качество распознавания
  вне контроля проекта;
- плохо справляется с профессиональным жаргоном (IT-термины, названия технологий);
- нет единообразия между браузерами — на iOS Safari отличается от desktop Chrome.

**Решение: пишем аудио в браузере (`MediaRecorder`), отправляем на сервер,
транскрибируем через OpenAI (Whisper / `gpt-4o-transcribe`)** — тот же провайдер,
что уже используется в `lib/interview.ts` и `/api/polish`, ключ уже настроен,
единое качество на всех платформах.

Компромисс: платно (по факту минут аудио) и требует round-trip до сервера
(задержка ~1-3 сек на конце записи). Это приемлемо — ввод не realtime-каптион,
а «наговорил → получил текст».

## 3. Архитектура

### 3.1 Новый API-роут

`app/api/transcribe/route.ts`

```
POST /api/transcribe
Content-Type: multipart/form-data
Body: audio (Blob, webm/opus или mp4, ≤ 25 MB — лимит OpenAI)

Response 200: { text: string }
Response 400: { error: 'Missing audio' }
Response 413: { error: 'Audio too long' }
Response 500: { error: 'Transcription failed' }
```

Логика:
```ts
const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY })
const transcription = await openai.audio.transcriptions.create({
  file: audioFile,
  model: 'gpt-4o-transcribe', // либо 'whisper-1' как fallback
  // language не указываем — автоопределение (юзеры пишут CV на разных языках)
})
```

Ограничения на входе:
- максимальная длительность записи на клиенте — **120 секунд** (защита от
  случайно оставленного открытым микрофона и от расходов на Whisper);
  таймер в UI, авто-стоп по истечении;
- максимальный размер файла — проверка на сервере (413, если больше 25 MB);
- rate limit: переиспользовать существующий `lib/usage.ts` — голосовой ввод
  считается как одно «действие» в дневном лимите пользователя (см. §6).

### 3.2 Новый компонент

`components/VoiceInputButton.tsx`

```tsx
type VoiceInputButtonProps = {
  onTranscript: (text: string) => void
  disabled?: boolean
}
```

Состояния: `idle → recording → transcribing → idle`.

Поведение:
- клик по микрофону → запрос `navigator.mediaDevices.getUserMedia({ audio: true })`;
- если permission denied → показать инлайн-подсказку «Разрешите доступ к микрофону
  в настройках браузера» (без модалок/алертов — в стиле проекта, текст под кнопкой);
- во время записи — кнопка меняет вид (пульсирующая красная точка + таймер `MM:SS`),
  повторный клик = стоп записи;
- после стопа — статус «TRANSCRIBING...» (как существующий паттерн `PREPARING...`
  в интервью), кнопка заблокирована;
- по готовности текста — вызывается `onTranscript(text)`, кнопка возвращается в `idle`;
- запись аудио идёт через `MediaRecorder` с `mimeType: 'audio/webm;codecs=opus'`
  (fallback на `audio/mp4` для Safari, который не поддерживает webm);
- ошибка транскрипции — текст ошибки инлайн, в стиле `text-red-400`, как у
  остальных error-стейтов в проекте.

### 3.3 Интеграция в существующие экраны

**`app/page.tsx`** — рядом с textarea (там же, где сейчас `ExampleChip` и
`LiveCharCounter`), добавить `<VoiceInputButton onTranscript={(t) => setMessage(prev => prev ? `${prev} ${t}` : t)} />`.
Транскрипт **дописывается** к уже введённому тексту, а не затирает его —
пользователь может печатать и диктовать вперемешку.

**`app/interview/page.tsx`** — рядом с textarea ответа (`answer` state), тот же
компонент: `onTranscript={(t) => setAnswer(prev => prev ? `${prev} ${t}` : t)}`.
Кнопка недоступна (`disabled`), пока `sending || finishing` — те же условия,
что уже блокируют поле ответа.

## 4. UX-детали

- Иконка микрофона — inline SVG, без внешних библиотек (в проекте их сейчас нет,
  не хотим тянуть `lucide-react` ради одной иконки — рисуем сами, как остальные
  элементы UI).
- Никаких браузерных `alert()`/`confirm()` — весь фидбек инлайн, в существующей
  цветовой палитре (`#0a0a0a` / `#1f1f1f` / `text-[#666]`).
- На мобильных (iOS Safari, Android Chrome) — `getUserMedia` требует HTTPS
  (Vercel даёт это из коробки) и явного user gesture (клик по кнопке — ок).
- Если браузер вообще не поддерживает `MediaRecorder`/`getUserMedia` —
  компонент не рендерится (фиче-детект на клиенте), textarea работает как раньше.

## 5. Приватность и хранение данных

- Аудио **не сохраняется** — ни в Supabase, ни на диске сервера. Roundtrip:
  клиент → `/api/transcribe` (буфер в памяти) → OpenAI API → текст → удаление буфера.
- Пользователю не нужно отдельного consent-экрана сверх стандартного браузерного
  промпта на разрешение микрофона — данных, кроме временного аудио-буфера, никто
  не хранит.
- Логи сервера не должны содержать сам аудио-контент (только факт запроса,
  длительность, статус).

## 6. Лимиты и стоимость

- Whisper/`gpt-4o-transcribe` — тарификация по длительности аудио (сек/мин).
  При лимите записи 120 сек — потолок стоимости одного вызова предсказуем.
- Встроить в существующий `lib/usage.ts`: голосовой ввод расходует ту же
  дневную квоту, что и `/api/polish` (или отдельный, более мягкий, лимит —
  на усмотрение продукта, т.к. это вспомогательное действие, а не основной
  результат). **Рекомендация: не считать отдельно** — квота уже есть на polish,
  voice input — это просто альтернативный способ заполнить то же поле.

## 7. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Пользователь не дал доступ к микрофону | Инлайн-подсказка, кнопка остаётся активной для повторной попытки |
| Запись длится > 120 сек | Авто-стоп, отправка того, что записано |
| Сеть упала во время отправки | `error` state, текст «Something went wrong. Try again.» — как везде в проекте |
| OpenAI вернул пустую транскрипцию (тишина) | Не вызывать `onTranscript`, показать «Didn't catch that — try again» |
| Файл больше 25 MB (маловероятно при лимите 120 сек, но перестраховка) | 413 с сервера, тот же error UI |

## 8. Что НЕ входит в этот этап (можно предложить отдельно)

- Live-транскрипция «на лету» (стриминг, показ текста по мере говорения) —
  требует WebSocket к OpenAI Realtime API, следующий этап, если понадобится.
- Голосовой вопрос **от интервьюера** (text-to-speech для вопросов) — отдельная
  фича, не путать с голосовым **вводом** ответа.
- Мультиязычный UI-переключатель языка транскрипции — не нужен, Whisper
  автоопределяет язык.

## 10. Проверка перед релизом

- `npm run lint` и `npm run build` — чисто.
- Ручное тестирование: Chrome desktop, Safari desktop, Chrome Android,
  Safari iOS (это самый частый источник багов с `MediaRecorder` — разные
  поддерживаемые MIME-типы).
- Проверить сценарий отказа в доступе к микрофону на каждой платформе.
- Проверить, что во время записи/транскрипции нельзя случайно засабмитить
  форму (кнопки `disabled` синхронизированы).
